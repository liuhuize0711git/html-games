# 围棋 · Go（单人 / 双人）

一个 **单文件网页围棋游戏**：`index.html`，双击就能玩，不需要联网、不需要任何外部文件。

---

## 1. 怎么玩

* **方式 A**：双击 `index.html`（或拖进浏览器）。
* **方式 B**：放进任意静态托管（GitHub Pages / Netlify / Vercel / 自己的服务器）后直接访问。

操作：**鼠标点棋盘交叉点** → 合法就落子，不合法会有提示。手机上点屏幕同样可以下。

---

## 2. 两种模式

| 模式 | 说明 |
| --- | --- |
| **单人（AI）** | 你选**执黑（先手）**或**执白（后手）**，AI 走另一边。AI 每手思考时间可选「快 / 普通 / 强」，越久越强（普通约 1.8 秒/手，会显示模拟了多少局）。 |
| **双人对战** | 两个人轮流在同一台设备上点棋盘下棋，没有 AI 参与。 |

两种模式都可以**随时结束对局**（右下「结束对局（数子）」），也可以「停一手」「悔棋」「认输」。

---

## 3. 规则与判定

* **中国规则（数子法）**：黑先，白贴 **7.5 目**；不能自杀；提子、**简单劫争**禁手都会判定。
* **停一手**：双方连续停一手 → 自动进入终局数目。
* **结束对局时的判定**：
  1. 先用**蒙特卡洛随机模拟**（几十万局采样，按时间）估计每个交叉点更可能归谁；
  2. 被对方完全包围的棋子会**自动判为死子**（棋盘上打红叉，可以从结果说明里看到），再按数子法精确计算：黑 X 目、白 Y 目（含贴目）、差多少、谁胜；
  3. 如果盘上**还有大量没争夺的区域**，就不会硬给一个目数，而是给出**双方胜率估算**（例如「黑 57% ／ 白 43%」）以及模拟的平均终局差距，并提示「想认真分胜负就继续把盘子走完再点结束对局」。
* **什么时候才真数目**：判断依据是**盘上还剩多少个「可以争的点」**（空点、且不是双方任何一方的真眼）。
  * 只剩不到 12% 的可争点，或者**双方都停一手** → 判为「盘面基本定型」，清点死子后**真数目**；
  * 还有一大堆点没定 → 只报「**现在已经围住的实空**（黑 X 目 / 白 Y 目）+ **双方胜率估算**」，
    并明确写着「现在还不能真数目」。中盘点结束对局不会再出现「一边 81 目、另一边 0 目」那种假终局。
* 「**显示地盘估算**」可以把每个点的归属概率画在棋盘上（越黑越可能归黑棋，越亮越可能归白棋），点一次就是一次形势判断。
* 「**形势判断**」按钮随时可以点，不结束对局也能看当前胜负估计。

## 3.5 棋谱（AI 自对弈学习）

棋谱用**以落子点为中心的 5×5 局部棋形**做索引：把周围 25 个交叉点是黑是白是空、连不连出界，
连同「该谁下」一起做 8 种对称（旋转 / 镜像）归一化，得到一个形状编号；棋谱里记的就是
「在**这个形状**下，把子下在中心点，自对弈里最后赢的比例」。

对局时引擎会用同一套编号去查表：**某个候选点的局部形状和棋谱里的某个形状一致、而且那手棋在
自对弈里胜率高，就先验加权、优先考虑它**。AI 思考完会显示「棋谱命中 N 处（这手在棋谱里 X 局中胜率 Y%）」。

* 页面里已经内置一份由 `selfplay.js` 生成的棋谱（**400 局自对弈、1000+ 个棋形**）。
* 点「**自对弈 +20 / +60 局**」可以让 AI 当场继续自己下棋学棋谱（约 0.5 秒/局，结束后自动保存到浏览器，
  AI 立刻就能用；页面上会显示棋形数量和学习进度）。
* 点「**导出棋谱文件**」把棋谱存成 JSON 文件（自对弈局数、黑胜率、每个棋形的 `[赢的局数, 出现局数]`）；
  文件只会进浏览器的「下载」文件夹，**不会自动进游戏记忆**。
* 点「**导入棋谱文件**」把导出的 JSON 读回来，与当前棋谱**合并**并存进浏览器记忆，AI 立刻使用 ——
  **不需要把它放到任何特定文件夹**。换电脑 / 换浏览器时就是「导出 → 拷过去 → 导入」。
* 「清空棋谱」会停用内置棋谱从头学（下次刷新会恢复内置棋谱）。

**棋谱存哪：**

| 位置 | 内容 |
| --- | --- |
| 浏览器 `localStorage` 的 `go_book` 键 | 页内「自对弈学习」和「导入」的结果，刷新/重开浏览器都还在 |
| 浏览器的「下载」文件夹 | 「导出棋谱文件」生成的 `go-book-<棋形数>patterns.json` |
| 工程的 `work/go/book.json` | 内置棋谱的源文件；改它再 `node build.js` 才会变成"新打开游戏时的默认棋谱" |

> 如果浏览器是隐私/无痕模式，或者 `file://` 下本地存储被禁用，页内学习可能不会被记住 ——
> 那就用「导出 → 导入」来保存棋谱。
* 想离线生成更多棋谱（可以放到 `book.json`，`node build.js` 会把它内嵌进 `index.html`）：

```bat
node selfplay.js 800 6 book.json     :: 800 局，每手思考 6ms
node build.js                        :: 重新打包单文件 index.html
```

> 说明：棋谱是从**较弱的高速度自对弈**里学出来的（每手只有几毫秒思考），
> 它提供的是「这种形状在自对弈里胜率偏向哪边」的统计直觉，用来给蒙特卡洛先验加权，
> 不是绝对正确的定式库；自对弈局数越多、胜率越可信。

## 4. AI 是怎么下棋的

1. **候选点生成**：排除自己的真眼、自杀手、劫争禁手；对每个点算一个静态先验（能提子、能救自己快被提的棋、贴着已有棋子、空边线上的单官降权）。
2. **蒙特卡洛评估**：对候选点做大量随机模拟（9 路盘约 **3000 局/秒**，所以「普通」难度每手能跑几千局），模拟里用「不填自己的眼」的走法，比纯随机棋力高很多。
3. **UCB1 分配时间**：先给每个候选点试几局，再按「胜率 + 探索项 + 先验」把剩下时间花在最有希望的点上。
4. **主动停一手**：把「停一手」当成一个候选一起评估；如果盘上只剩自己眼的单官、或者已经没有值得下的点，就会停手并进入数目。

实测：AI 用 40ms/手（约 130 局模拟）就能 3:0 全胜「不填自己眼」的随机对手；用「普通」难度（约 1.8 秒/手，2000 局左右）对随机对手是 81:0 完胜。

## 5. 说明

* 单文件内部分成两段脚本：`GoEngine`（纯逻辑：棋盘 / 规则 / 模拟 / 数目，不碰 DOM）与界面层（Canvas 绘制 + 交互）。引擎可以直接抽出来在 Node 里跑测试。
* 浏览器控制台里有调试入口：`window.__go.engine`、`window.__go.getGame()`。
* 想改棋盘大小或贴目：改 `ui.js`/`index.html` 里的 `E.newGame(9, 7.5)`（引擎本身支持 9 / 13 / 19 路，但 AI 的模拟次数是按 9 路调的，19 路会明显变弱）。
* 形势判断是**统计估算**，早期盘面（几乎空盘）时随机模拟会略微偏向先手，仅供参考；真正分胜负请把盘面走完再点「结束对局」。
* 本作为个人娱乐用途的原创实现，未使用任何第三方素材。
